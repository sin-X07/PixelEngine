# 主菜单场景综合质量提升计划：灰尘漂浮重做 + 背景建筑提质

日期：2026-11-24。给 Codex 一次做完、分场景校验、最后统一验收。
范围：dust_2（盐市）与 mirage（靛蓝商旅院）的漂浮灰尘重做；三张场景（盐市、雨历庭、商旅院）的背景建筑提质到与前景建筑同一品质。

## §0 已核实的现状（不要重新论证，直接当事实用）

### 问题 1：灰尘漂浮太假
- 现在的灰尘**不在 Blender 场景里，在游戏代码里**：`Menu3D.cpp` `DrawEnvironment()`（约 1275–1310 行），每帧程序化画出。
  - 沙漠场景（dust_2、mirage）：100 个扁平纯色四边形，尺寸全一样（0.08），颜色全一样（0.78/0.62/0.36），透明度全一样（0.09）；非沙漠（雨历庭）：35 个，尺寸 0.018，透明度 0.18。
  - 运动是直线传送带：`x = fmod(phase + i*1.91, 24) - 12`，所有颗粒同一速度沿 +x 平移，到边缘瞬移回起点（肉眼可见的跳变）；无上下漂移、无湍流、无随机。
  - 深度只有一层：`z = -3.3 - fmod(i*.711, 3.2)`，全部挤在演员身后 3.2 个单位内，无近中远层次、无视差。
  - 无光照关系：纯色扁平，不随光柱亮暗变化，均匀洒满整个画面，不是在光照到的地方才有。
  - 无柔边、无贴图：每个颗粒是一个硬边矩形（高只有宽的 0.45 倍），近看就是小色块。
  - 沙漠场景另有 12 个"灰尘团"（triangle fan，alpha 0.065，3.8×0.8 的扁椭圆，中心到边缘淡出），颜色均匀、无噪点纹理，像平贴的污渍。
- Blender 场景脚本里**没有漂浮灰尘代码**（已核实）：`tools/menu-scenes/create_scenes.py` 无灰尘粒子；脚本里的 "dust" 只是地面贴图的 dusty 图层（`surface_finish.py:24-25`）和蒙尘玻璃（`salt_market.py:485`），与漂浮无关。
- 结论：假的原因是实现方式本身——纯色矩形 + 传送带 + 单层 + 无光。修的办法是把灰尘搬进 Blender 做成真实几何（见 §2），不是调几个数字。

### 问题 2：背景建筑只是纯色模型
- 已核实：背景层元素是单材质简单几何——mirage 的 `Distant cupola`（车削体，`haze` 材质，32 段，`indigo_caravanserai.py:44`）、salt_market 的 `Distant shade recess`（box，`slate` 材质，`salt_market.py:753`）；前景建筑则有贴图、倒角、门窗、遮阳篷等完整细节（9/7/7 张内嵌 JPEG，材质数 21/13/15）。
- 差距不在数量，在品质维度：无贴图、无倒角、无门窗与结构细节、无明暗变化——远看就是色块，破坏三层纵深的可信度。

### 共同约束（PIX-39 定下的，不变）
- 渲染器是固定管线 OpenGL 1.x（零 shader，GL 2.1 兼容模式）；loader 只读 base color 贴图 + 系数，粗糙度/金属度/法线全忽略。灰尘与建筑都必须以**真实几何 + base color 贴图**的形式进 GLB，Blender 粒子系统 / Geometry Nodes 修改器**不导出**到 glTF——节点必须 Realize 成真实几何，运动必须烘焙成关键帧。
- 动画只有一条 `Menu_Environment` clip（0–120 帧 @30fps，4 秒循环），灰尘漂移必须烘焙进这条 clip，首尾帧姿态一致、无跳变。
- **不设预算限制**（Sun 2026-11-24 23:44 决定）：verts、GLB 体积、材质数、贴图尺寸均不设上限，Codex 按视觉效果尽情发挥；只记录实测值（顶点数、GLB 体积、材质数、贴图尺寸、菜单初始化与帧时间）写入验收文档，供 Sun 看成本，不设卡。`validate_scenes.py` 0 findings；`gameplay_tests` 1750 通过 / 6 失败（基线不变）；`menu_art_review` 通过。
- MCP blender 服务器已配（`~/.codex/config.toml`，127.0.0.1:9876）；blender-skills 已装到 Codex（`~/.codex/skills`，28 个，已核实）。
- 不可破坏：不动游戏本体逻辑（除 §2-A4 指定删除的灰尘代码）、不改场景布局、不删除任何资产与数据（§2-A4 是 Sun 点名换掉的旧实现，且有新实现替代，删前须先验证新实现已进游戏可见）、不提交、不 push、不切分支；每张场景独立验证再做下一张；一个任务一次做完，中间不等 Sun 确认，但逐场景校验不能省。

## §1 目标与总验收标准

- 灰尘：像真灰尘——只在光照到的地方、大小亮度不一、慢速对流漂移、有近中远三层纵深、柔边、4 秒循环无跳变；进游戏截图与 Blender 视口一致。
- 背景建筑：与前景建筑同一品质——有贴图、有倒角与结构细节、有门窗、有明暗变化；远景仍保留空气透视（比前景更淡、对比度更低），不是把雾去掉。
- 性能只记录、不设限：菜单初始化与帧时间实测值写入验收文档，供 Sun 看成本。
- 每张场景独立验证（截图 + validate + 测试）再做下一张；全部做完统一验收，Sun 目检通过才算完。

## §2 Part A——灰尘漂浮重做（dust_2、mirage）

### A1 诊断（先确认，再动手）
- 在 Blender 里打开两张场景 + 进游戏截全屏图，逐项确认 §0 的 6 条假点（同尺寸、同色、同透明度、传送带、单层、无光），把现状截图存入证据目录。
- 读 skill：`blender-geometry-nodes`、`blender-lighting-lookdev` 的 SKILL.md。

### A2 用 Geometry Nodes 做灰尘，再 Realize 成真实几何
- 做法（参考业界成熟做法：Icosphere → Mesh to Points 撒点 → 4D Noise 驱动漂移 → Instance on Points 挂小颗粒）：
  - 撒点：Icosphere → Mesh to Points；Noise Texture 切 4D（Scene Time / 帧 ÷100 → W），Set Position 做漂移；Instance on Points 挂 1 细分 icosphere（42 顶点/个），scale 按对数分布 0.02–0.06（多数极小、少数稍大）。
  - 数量：每场景 200–400 个起步（参考值：Sapphire Dust 默认约 200，Dustlit 上限 900）；最终数量以视觉效果为准，不设上限。
  - 分布：**只在光照到的地方**——光柱、窗洞、棚隙下方及其边缘 0.5m 内；暗处不放。按太阳方向与窗洞位置手工框选 emitter 体积，不要全场景均匀撒。
  - 纵深：分近/中/远三层（按相机距离分档）；近层颗粒大、移动快（视差）、亮度低；远层颗粒小、移动慢、光柱内更亮。
  - 材质（共用 1 个新材质，`blender-pbr-materials`）：暖色半透明（阳光尘偏暖），alpha 按大小分档 0.12–0.30（大颗粒更淡）；icosphere 小尺寸下无硬边，不用贴图 quad（游戏无 billboard，quad 会穿帮）。
  - 完成后 **Realize Instances** 成真实几何，删掉 GeoNodes 修改器（不进 GLB）。
- 备选（仅当 GeoNodes 路径受阻）：粒子系统——emitter 立方体，gravity 0，turbulence 力场（strength 适中、flow 低）+ 小 vortex 打散结块，render as object（小 icosphere）；同样必须烘焙成关键帧几何。二选一，GeoNodes 优先。

### A3 漂移烘焙进 Menu_Environment clip
- 把 A2 的漂移烘焙成节点关键帧，写进现有的 `Menu_Environment` clip（0–120 帧 @30fps）；漂移幅度小（±0.1–0.3m），速度慢——**对流不是风**，不要跟着 wind clip 的速度走；第 0 帧与第 120 帧姿态一致，循环无跳变。
- 读 skill：`blender-simulation`（运动参考）、`blender-export-pipelines`（GLB 动画导出）。

### A4 删游戏里的程序化灰尘（顺序不能反）
- 先把新 GLB 推进游戏、截图确认新灰尘可见，再删 `Menu3D.cpp` `DrawEnvironment()` 里的程序化灰尘（quads 循环 + 12 个 dust-bank triangle fan，约 1275–1310 行）。不要两套叠加。
- 删完重编、跑 `gameplay_tests`、截图确认画面干净。

### A5 验证（每张场景）
- Blender 视口截图 + 进游戏全屏截图（前后对比）；`validate_scenes.py` 0 findings；`gameplay_tests` 通过；菜单初始化与帧时间记录；`blender-asset-qa` 跑一遍（数量、尺寸分布、材质数、动画首尾一致；预算只记录、不设限）。

## §3 Part B——背景建筑提质（三张场景）

### B1 审计（先列清单，再动手）
- 在 Blender 里逐张场景列出背景层全部对象：名字、位置（距相机距离）、材质、贴图（有/无）、顶点数；对照前景建筑标准逐项列差距清单（无贴图 / 无倒角 / 无门窗 / 无结构细节 / 纯色）。
- 读 skill：`blender-asset-qa`、`blender-game-optimization` 的 SKILL.md。

### B2 建模提质（Mid-poly 工作流，与精修提示词同一标准）
- 读 skill：`blender-hardsurface-modeling`（Mid-poly：bevel + Weighted Normal，不烘焙）。
- 做法：bevel 2–4cm（大件）/ 0.5–1cm（小件），2–3 段，MITER_ARC；圆柱 ≥24 段、穹顶 ≥32 段、拱 ≥16 段；Smooth by Angle（30°）+ Weighted Normal（FACE_AREA，keep_sharp，weight 50）；只在真曲线处用一级细分。
- 细节：按前景同款补结构——门窗、屋檐、遮阳篷/棚、招牌、烟囱、女儿墙、拱券；细节密度由 Codex 按视觉效果定，远景不强制减半；唯一要求是**禁止纯色**——每个面必须有贴图与明暗变化。
- 读 skill：`blender-lighting-lookdev`（远景仍要嵌进场景光照，不要自发光）。

### B3 材质提质
- 读 skill：`blender-pbr-materials`、`blender-texture-baking` 的 SKILL.md。
- 优先复用现有材质与贴图集（前景同款墙面、屋顶、石材）；新材质与贴图尺寸不设限，按效果定；AO 烘焙进 base color（或乘进贴图），不要新增贴图通道（loader 不读）。
- 远景材质亮度与对比度低于前景（空气透视是纵深的一部分，见 B4），不要为了"清晰"把远景调得和前景一样亮。

### B4 大气透视保留
- 背景建筑保持雾色与空气透视（现有雾 16→34 与逐场景 haze 颜色不动）；远景淡、对比度低是正确的纵深表现，提质的是"有细节的淡"，不是"和前景一样实"。
- 验收时截图对照：前景实、背景淡但有细节，中间有过渡。

### B5 验证（每张场景）
- Blender 视口截图 + 进游戏全屏截图（前后对比，同一机位）；`validate_scenes.py` 0 findings；`gameplay_tests` 通过；`blender-asset-qa` 跑一遍（材质数、顶点数、GLB 体积、贴图尺寸）；菜单初始化与帧时间记录。
