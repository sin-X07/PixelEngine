## 核实结论（写计划前先说清的三件事）

### 1. G44、G45 确实已经实现 —— Sun 说得对
- **G44 受击方向已实现**：完整链路都在代码里——受击时记录方向（`CS2DGameCombat.cpp:418-421`，`atan2(-bullet.vy, -bullet.vx)`，即子弹来源方向，0.5 秒有效期，最多 4 个方向并存）；`damageDirections_`（`CS2DGame.hpp:1248`，`array<DamageDirection, 4>`）每帧衰减（`CS2DGame.cpp:1164`）；渲染是 `GameUI::DrawDamageDirections`（`GameUI.cpp:2827`，屏幕边缘红色辉光弧，高斯衰减、四层向内淡出），`Engine.cpp:2550` 每帧调用。验收：背后中枪 → 屏幕后方出红弧；多方向并存。
- **G45 击杀栏已实现**：击杀栏现在是深色圆角行 + 自己相关行边框高亮 + 击杀者/被击杀者阵营色名字 + 武器图标（`GameUI.cpp:2550` 起，图标 76×24）+ 滑入动画 + 淡入淡出；数据齐全（`Engine.cpp:2450-2451`，含 weapon iconPath、双方阵营、personal 标志）。爆头仍未实现——审计已说明爆头需在弹道里加命中部位概念，本次也不做（见“明确不做”）。
- **连带影响 PIX-34 的 G39**：PIX-34 G39（受击方向提示）的方向部分，已被 G44 这套实现覆盖，不用重做。G39 剩下的只有一件事：把两个反馈计时器接线——其中命中标记计时器已经接上了（`CS2DOverlay.cpp:191`），只剩受击红闪（见下条）。Codex 做 PIX-34 G39 时先核实、不要重复实现；Sun 统一验收 PIX-34 时可据此更新 G39 的范围。

### 2. 受击红闪目前是死的 —— G46/G39 都要先接它
- `damageFlashTimer_ = 0.30f`（`CS2DGameCombat.cpp:424`）只赋值、在 `CS2DGame.cpp:1166` 递减；`GetDamageFlashTimer()`（`CS2DGame.hpp:685`）和 `DrawDamageVignette`（`CS2DRenderer.cpp:1802`）在全仓**零调用**。也就是说：现在玩家被击中时，除了 G44 的方向红弧，**没有任何全屏红闪**——审计时代的均匀红边调用已经不在了。这是 G46“被击中反馈”要修的第一件事，也是 PIX-34 G39 剩下的最后一件，两处是同一项工作，不要做两遍。

### 3. G43 口径说明：审计原项与 Sun 的描述不是同一件事，计划里两件都做
- 审计 G43 的原项是 **HUD 上找不到余额**（P0）：`ictx.money` 每帧都填了（`Engine.cpp:2425`），但 `DrawInGame`（`GameUI.cpp:2359` 起）从没画它；钱只出现在买枪菜单（`:1707`“余额: $%d”）和记分板（`:2655`）。
- Sun 的描述是**买枪菜单页面美术**（审美平庸、重要信息视觉权重太少、优化到发行效果）。
- 计划把 G43 拆成两件：G43-a HUD 常驻余额（审计原项，P0，必须做）；G43-b 买枪菜单视觉优化（Sun 的要求）。另注意与 PIX-32 G6 的重叠：G6 已在修买枪菜单的枪身比例/布局压缩，G43-b 是视觉设计层（层级、字阶、配色、状态表达），在 G6 的布局基础上做，不重做 G6。

## B. G43（P0）经济信息视觉强化：HUD 常驻余额 + 买枪菜单到发行效果

### G43-a HUD 常驻余额（审计原项）
- 现状：数据已到 HUD（`Engine.cpp:2425` `ictx.money = status.money`），`DrawInGame` 没画。顶部计分条（`GameUI.cpp:2359` 起，560×76）只有队名/比分/存活/计时/阶段；右下武器面板有武器图标 + 弹药 `x / y` + 换弹提示，无余额。
- 改法：在右下武器面板弹药行下方加一行余额（金色、`$` + 数字，字阶与弹药行一致或略大，带 `$` 图标感——用金色 `$` 字符即可，不新画图标）；买枪窗口期（Freeze/Buy 阶段）余额行高亮（金色加亮 + 轻微脉冲，提示“现在能花”），窗口期外恢复常态。数据直接用 `ctx.money`，不新增字段。
- 验收：对局全程右下角可见余额；进购买期余额行变亮；买完枪数字立即更新；1280×720 下不与弹药行/拆包钳行重叠。

### G43-b 买枪菜单视觉优化到发行效果（Sun 的要求）
- 现状：买枪菜单已是 ImGui 卡片式（`GameUI.cpp:1680-1912`，680×560 居中，5 组：主武器/副武器/近战/投掷物/护甲；卡片 208×70、每行 3 张；图标 40px；名称/类别·开镜/价格；角标：已装备/已带满/钱不够/阵营不符/退款；悬停/按下/禁用态；类别色条）。基础不差，缺的是视觉层级。
- 改法（只动视觉层，不动购买逻辑、不动 G6 的布局）：
  1. **余额权重**：顶部余额从普通文本升级为独立余额块——字号加大一级、金色、左侧加 `$` 标志、买不起当前选中项时余额数字变红（与“钱不够”角标同色）；买枪窗口期倒计时（剩余秒数）放余额块旁，窗口关闭前 10 秒变红。
  2. **价格权重**：价格字号加大、与名称同级视觉重量；买不起的卡片价格置灰 + 红色删除线效果（不用改文字，用颜色 + 透明度表达）；已装备的卡片价格区改为“已装备”绿标。
  3. **字阶与间距**：名称 15→16、类别行 12→13、组标题加粗 + 组间间距加大；卡片圆角与描边统一（悬停描边 2px 品牌蓝已存在，保持）。
  4. **顶部信息行**：标题“购买菜单”加副标题（当前回合 + 购买窗口剩余时间），三段式布局：左标题、右余额块，中间留白。
  5. **空状态与反馈**：购买成功/失败的闪现提示（`flashText`，已有 1.6/2.2 秒）保持，但失败时整行红底淡入而不是纯文字（已有颜色，补底色）。
- 不做：不改卡片尺寸与每行 3 张的布局（那是 G6 的范围）；不加武器数值对比（伤害/射速等参数面板不在本次范围）；不改购买流程与退款逻辑。
- 验收：Sun 按“发行效果”目视验收——余额一眼可见、买得起/买不起一眼可分、组与组之间不糊；G6 的布局验收仍按 PIX-32 走，两项不互相等。

## C. G46（P1）命中反馈强化 —— 不加伤害数字

- 现状核实：
  - **视觉**：命中标记已接线（`CS2DOverlay.cpp:191`，`GetHitMarkerTimer()` → `DrawHitMarker`，白色 X，0.18 秒内淡出），但击杀与非击杀是同一个白 X，无护甲区分。受击红闪是死的（见核实结论 2）。
  - **音效**：已基本就位——玩家子弹命中 BOT：击杀播位置性 `KILL`、命中播位置性 `HIT`（`CS2DGameCombat.cpp:391-393`，`PlaySoundAt`，远了听不清）；玩家被击中：2D 非位置性 `ARMOR_HIT`（有护甲）/`HIT`（无护甲）（`:426`）；玩家阵亡：2D `KILL`（`:1037`，是“你被击杀”的确认音，不是击杀确认音）。`HIT` / `KILL` / `ARMOR_HIT` 音源文件都已存在（PIX-33 音频工作），本次不需要新录音。
- 改法：
  1. **命中标记分态**：`hitMarkerTimer_` 从纯计时器升级为“计时 + 种类”——击杀（击杀瞬间，红色、放大 1.5 倍、延长到 0.30 秒）、命中护甲（目标 `armor > 0`，蓝色/黄色，大小不变）、普通命中（白色不变）。种类在 `CS2DGameCombat.cpp:379` 置位时按目标状态定（击杀分支与护甲判断当时都在作用域内）；渲染仍在 `CS2DOverlay.cpp:191` 处按种类取色/取尺寸。**不加伤害数字、不加飘字**（Sun 明确不要）。
  2. **受击红闪接线**：`GetDamageFlashTimer()` 接到 `DrawDamageVignette`（`CS2DRenderer.cpp:1802` 已有实现，alpha 按计时器 0.30 秒衰减）。这是 PIX-34 G39 剩下的最后一件——G46 与 G39 在此交汇，Codex 只做一次，验收时 G39 与 G46 共用这一项。红闪与 G44 的方向红弧叠加显示（红闪均匀、红弧定向，互不冲突）。
  3. **击杀确认音改非位置性**：玩家击杀敌人时，在现有位置性 `KILL`（`:391`）之外，叠加一层 2D 非位置性 `KILL` 确认音（与 `:1037` 的用法一致，音量略低），保证远距离击杀也能听见确认。位置性那层保留（近处仍有方向感）。
  4. ** outgoing 护甲命中音**：玩家子弹命中带护甲的 BOT 时，播 `ARMOR_HIT` 而不是 `HIT`（与 `:426` 被击中侧的区分逻辑一致，目标 `armor > 0` 当时可读）。不新增音源文件。
- 验收：命中白 X、击杀红大 X、打护甲变色，三态肉眼可分；被击中时红闪 + 方向红弧同时出现；远距离击杀能听见确认音；打护甲的枪声与打肉的枪声可分；无任何伤害数字出现。

## D. G47（P1）空仓与换弹反馈

- 现状核实：
  - 弹匣打空且有备弹：已有 CLICK 声（`CS2DGameCombat.cpp:179-186`，`!reloading && reserve > 0` 时播 `CLICK`）+ 自动 `StartReload`，两者叠加是“咔哒 + 拉栓”。
  - 弹匣打空且备弹为 0：`StartReload` 直接 return（`:1103-1112`，`reserve <= 0` 时无提示），扣扳机**零反馈**——审计的问题仍在。
  - 换弹提示只有“换弹中...”一行字（`Engine.cpp:2412-2413`），画在固定 y=512 像素处（`GameUI.cpp:2753`，不随分辨率缩放居中）；无进度条/圆环；HUD 只收到 `reloading` 布尔值（`ictx.hasNoWeaponHint`），没有换弹进度。
- 改法：
  1. **换弹进度条**：新增 `GetReloadProgress()`（0..1，未换弹时 0；值 = `1 - reloadTimer / reloadTime`，`reloadTimer`/`reloadTime` 现成，`CS2DGameCombat.cpp:1112/1176`），经 `ictx` 传到 HUD；在右下武器面板弹药行下方画一条细进度条（与弹药行同宽，金色填充，换弹完成时闪一下消失）。同时“换弹中...”文字保留，但位置从固定 y=512 改为分辨率自适应（相对屏幕高度居中偏下，与提示区对齐），不再写死像素。
  2. **0/0 空仓反馈**：弹匣 0 且备弹 0 时扣扳机：显示“没有备弹”文字（复用提示区，红色，1 秒）+ 播新 `DRYFIRE` 空仓声（`sfx_dryfire.wav`，0.120 秒、-3 dBFS，2026-11-17 已推入 `assets/audio/`）。**注意：`SoundEffect::CLICK` 是 UI 按钮点击声（`ui_click_1..5.ogg`，`AudioManager.cpp:156-163`），不能用于空仓；需新增 `SoundEffect::DRYFIRE` 枚举并在 0/0 分支调用。**加 0.3 秒节流——按住扳机不连续刷屏/刷音。
  3. **换弹中途打断**：换弹被打断（切枪/死亡）时进度条立即消失，不残留（`reloadTimer` 清零处已有，HUD 跟 `reloading` 布尔值走即可）。
- 验收：换弹时进度条从空走到满，与换弹音时长对齐；0/0 扣扳机出红字 + 一声咔哒，按住不刷屏；720p 下提示文字位置正常（不再固定 512）；换弹打断后进度条不残留。

## G. G52（P2）结算期与回合中归为一个状态

- 现状核实：
  - 状态机：`Freeze → Buy → Live → RoundEnd（4.0 秒）→ Freeze`（`RoundManager.hpp`，`endTime = 4.0f`；`RoundManager.cpp:28-58`）。
  - 结算期行为（`CS2DGame.cpp:1020-1043`）：`canMove = !frozen`（结算期仍可移动/拾取），`canAct = !frozen && !ending`（结算期不能换弹/潜行），但 `UpdatePlayerShooting` 在 `canMove` 为真时照常跑——**结算期可移动、可开枪、可投掷**，代码注释原话就是“结算展示期与回合中完全一致”。BOT 也一样（`canMove` 时 `UpdateBOTs` 照常跑）。
  - `IsRoundEnd()` 的调用点：`CS2DGame.cpp:1022`（ending 门）、`CS2DGameRound.cpp:463/505`（防重复结算）、`:28`（RoundEnd→Freeze 时 `BeginNewRound`）。比赛结束时状态机冻结、停在最后一回合结算画面（`CS2DGameRound.cpp:16-21`，`matchOverTimer_`）。
  - HUD 阶段文案有“回合结束”一项（`GameUI.cpp` `DrawInGame`，`phases[] = {"热身","冻结","购买","交战","回合结束"}`）。
- 改法（按 Sun 的决定：两个状态功能一致，合并为一个）：
  1. **删 `RoundPhase::RoundEnd`**：Live 增加“回合已决”标记（胜者 + 决出时刻 + 4 秒展示计时）。`EndRound(winner)` 改为只设标记 + 走现有结算动作（`ApplyRoundResult`：比分、胜负音、公告 `announcement_` 2.4 秒、发钱 `GrantRoundEndMoney`），**不切阶段**。
  2. **4 秒展示计时留在 Live 里跑**：`RoundManager::Update` 在 Live 下若已决且 4 秒走完 → 下一回合 Freeze（`roundNumber++`、重置，与现 `RoundEnd→Freeze` 同款）；`BeginNewRound` 的触发点从“`before==RoundEnd && after==Freeze`”（`CS2DGameRound.cpp:28`）改为“已决计时走完 → Freeze”。
  3. **所有 `IsRoundEnd()` 调用点收敛到已决标记**：`CS2DGame.cpp:1022` 的 `ending` 门删除——`canAct = !frozen`，结算窗口内换弹/潜行也与回合中一致（这正是“全部一致”的含义）；`CheckWinConditions` 与 `ApplyRoundResult` 的防重复结算改查已决标记；`CS2DGameRound.cpp:463/505` 同理。
  4. **比赛结束仍冻结**：`MatchOver` 时状态机冻结、停在已决画面（`matchOverTimer_` 逻辑保留，只是触发条件从 RoundEnd 改为“已决 + 比赛结束”），不进入下一回合 Freeze。
  5. **HUD 文案**：`phases[]` 删“回合结束”一项；已决窗口内阶段文案显示“交战”，胜负由中央公告（“回合胜利/失败”）表达。死斗无回合，不动。
- 验收：回合决出后 4 秒内：公告显示，移动/开枪/投掷/换弹/潜行全部可用，与回合中无差别；窗口内击杀正常计 K/D 与金钱（不再有“结算期击杀”的特殊概念）；4 秒到 → 下一回合 Freeze；比赛结束时停在最终画面、不进下一回合；全仓 grep `RoundEnd`（除历史注释外）零命中；`build-release` 编译通过；`gameplay_tests` 全过。
