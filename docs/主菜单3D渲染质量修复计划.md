# PixelEngine 主菜单 3D 渲染质量修复计划

日期：2026-11-24。给 Codex 一次做完、分阶段校验、最后统一验收。
背景：Blender 里好看的场景进游戏又模糊又没质感。已逐行核实根因（见 §0），不是模型问题，不返工模型。

> **不设预算限制（Sun 2026-11-24 决定）：本计划所有数值上限一律取消——分辨率、顶点数、GLB 体积、材质数、贴图尺寸、初始化与帧时间均不设限，Codex 按视觉效果尽情发挥；性能与体积只记录实测值写入验收文档，不设卡、不降画质。**

## §0 已核实的现状（不要重新论证，直接当事实用）

- 渲染器是**固定管线 OpenGL 1.x**，零 shader（全仓无 `glCreateShader` / `glCreateProgram`）。上下文为 GL 2.1 兼容模式（`Menu3D.cpp:302-305`），GLSL 1.20 可用。
- 模糊主因：`Engine.cpp:512` 写死 `menu3D->Initialize(renderer, 1024, 576)`——场景只以 1024×576 渲染，经 SDL 线性放大拉满全屏（2560×1600 上是 2.5 倍）。`ReadbackToTexture()` 每帧 `glReadPixels` → CPU 缓冲 → 软件 sRGB 编码 → `SDL_UpdateTexture`。
- 没质感主因：光照只有一盏主光（`Menu3D.cpp:356-361`，环境光 0.18/0.20/0.24，漫反射暖色 0.88/0.84/0.76）+ 一盏聚光灯（GL_LIGHT1），无阴影、无 AO、无环境光；loader 只读 `base_color_texture` + `base_color_factor`（`Menu3DModel.cpp:322,376`），粗糙度/金属度/法线/遮挡全忽略，所有材质同一套平淡 Lambert 响应。按场景调光的代码已存在（`Menu3D.cpp:1259-1270`，sun/warmth/skylight + 雾 16→34），不要删，继续沿用。
- 次因：无各向异性过滤（只有 `GL_LINEAR_MIPMAP_LINEAR`，`Menu3DModel.cpp:292-293,740-746`，mipmap 生成用 `0x8191` 常量写法）；贴图以 `GL_RGBA` 上传（无 sRGB 解码），光照按线性算完再软件转 sRGB——输入端缺解码，颜色发灰。
- 已有的好东西不要动：MSAA 4x（`Menu3D.cpp:312-313,353`，失败回落 0x）；mipmap 已开；深度 24 / 透明 8；`glShadeModel(GL_SMOOTH)`；逐场景光照微调。
- 绘制路径：模型用顶点数组（`glTexCoordPointer` / `glVertexPointer` / `glNormalPointer` + `glDrawElements`，`Menu3DModel.cpp:766-773`）；方块/圆环/小鸡用立即模式 `glBegin(GL_TRIANGLES)`。兼容模式下顶点数组会自动喂给 shader 的内置 attribute（`gl_Vertex` / `gl_Normal` / `gl_MultiTexCoord0`），这是 P3 低风险迁移的关键。
- **不设预算限制**：verts、GLB 体积、materials、贴图尺寸均不设上限（原 PIX-39 预算一律取消），Codex 按视觉效果尽情发挥；只记录实测值写入验收文档。`validate_scenes.py` 0 findings；`gameplay_tests` 1750 通过 / 6 失败（6 条为无显示环境 SDL 失败，基线）；`menu_art_review` 通过。

## §1 目标与总验收标准

- 全屏截图与 Blender 同角度渲染并排对比：边缘清晰、贴图不糊、材质分得出石头/金属/木头、暗部可读、高光不爆。
- 性能只记录、不设限：菜单初始化与帧时间实测值写入验收文档，供 Sun 看成本（`glReadPixels` 回读是主要成本，见 T1）。
- 每阶段独立验证（截图 + validate + 测试）再进下一阶段；全部做完统一验收，Sun 目检通过才算完。

## §2 P0——清晰度三件套（先做，见效最大）

### T1 分辨率：不再写死 1024×576
- 改哪里：`Engine.cpp:512`、`Menu3D::Initialize`、`Menu3D::InitGL`（隐藏窗口尺寸跟随）、`CaptureScenePreviews`（预览仍用主纹理分辨率，不另开路径）。
- 怎么做：用 `SDL_GetRendererOutputSize(mainRenderer, &w, &h)` 取主渲染器的物理输出尺寸作为渲染分辨率，不设上限，直接按物理全尺寸渲染；实测菜单帧时间与初始化时间并记录在案。隐藏 GL 窗口按同一尺寸建。`glViewport` 与 `ReadbackToTexture` 的 `glReadPixels` 尺寸跟随 `width_` / `height_`（已是变量，不用改逻辑，只改取值来源）。
- 验收：全屏截图，文字与几何边缘明显变锐；初始化与帧时间实测值记录在案。
- 回退：不设上限、不降画质；若帧时间明显变差，把实测值写进验收文档报 Sun，由他定夺。

### T2 各向异性过滤
- 改哪里：`Menu3DModel.cpp:740-746` 贴图上传处（wrap/min/mag 同一位置）。
- 怎么做：`glGetString(GL_EXTENSIONS)` 含 `GL_EXT_texture_filter_anisotropic` 时，`glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAX_ANISOTROPY_EXT, min(8, maxSupported))`；`GL_MAX_TEXTURE_MAX_ANISOTROPY_EXT` 用 `glGetFloatv` 取。Windows GL 1.1 头文件里没有这两个常量，按现有 `0x8191` 的写法自行 `#define`（`0x84FE` / `0x84FF`）。不支持则保持现状，不报错。
- 验收：斜视角地面贴图（盐市地面、庭院石板）明显变清晰；截图对比。

### T3 sRGB 贴图解码
- 改哪里：`Menu3DModel.cpp:749` 的 `glTexImage2D`。
- 怎么做：internal format 由 `GL_RGBA` 改为 `GL_SRGB8_ALPHA8`（`0x8C43`，GL 2.1 核心可用）。`ReadbackToTexture()` 的软件 sRGB 编码保留——贴图解码到线性、光照线性算、输出再编码，管线就通了，不要重复编码。
- 验收：截图颜色不再发灰，与 Blender 渲染的同一材质色板肉眼一致；色卡抽查（取一处已知材质的屏幕像素值与 Blender 对照，偏差说明原因）。

## §3 P1——固定管线内光照加强（不动 shader，先把现有管线用到头）

### T4 补光
- 改哪里：`Menu3D.cpp:356-361` 的 LIGHT0 与 `Menu3D.cpp:1259-1270` 的逐场景调光块。
- 怎么做：加一盏补光 GL_LIGHT2，从相机对侧打低强度冷色光（强度约为 LIGHT0 漫反射的 30–40%），抬暗部；环境光下限抬到 0.25 左右（逐场景微调，盐市暖、雨历庭冷、商旅院中性）。逐场景的 sun/warmth/skylight 结构保留，只调数值。
- 验收：暗角可读、高光不爆；三场景截图各一张。

### T5 镜面（按材质区分高光）
- 改哪里：模型绘制处（`Menu3DModel.cpp` 的 primitive 绘制，`prim.color` 附近）与材质加载处。
- 怎么做：读 `pbr_metallic_roughness.metallic_factor` / `roughness_factor`，映射为 `glMaterialfv(GL_SPECULAR, …)` 与 `glMaterialf(GL_SHININESS, (1 - roughness) * 128)`；metallic 高的给偏白高光、roughness 高的给弱高光。固定管线镜面是逐顶点 Gouraud，效果有限，预期写清楚：只求材质间拉开差距，不求镜面质感。
- 验收：金属件（灯具、铜器）与石材在同一光照下高光 visibly 不同。

### T6 雾与氛围微调
- 改哪里：`Menu3D.cpp:1254-1258` 雾参数。
- 怎么做：雾起止（现 16→34）按场景微调，盐市远景雾更重、雨历庭更轻，保持空气透视；雾色与天空色一致。
- 验收：远景有纵深、近景不受雾洗白。

## §4 P2——Blender 烘焙（资产侧，把 Blender 的光影带进游戏）

### T7 AO 烘焙进贴图
- 怎么做（Blender MCP + blender-skills，参考已装的 blender-asset-qa 流程）：在 Blender 里给三张场景烘焙环境光遮蔽（AO，可选再加漫反射直接光），乘进 base color 贴图后重新导出 GLB（源 .blend 与未烘焙贴图备份保留，不删除）。GLB 重新跑 `validate_scenes.py` 到 0 findings；GLB 体积与材质数不设限，只记录。
- 验收：截图出现接触阴影与暗角深度；validate 0 findings；`gameplay_tests` 通过；GLB 体积与材质数记录在案。
- 注意：烘焙是乘进贴图，不动渲染器；若 P3 完成，烘焙 AO 与 shader 的 AO 贴图不要叠加两遍（P3 启用时用 shader 的 occlusion 通道，烘焙版只留作回退）。

## §5 P3——Shader PBR 渲染器（真正质感，最大的一块）

目标：把固定管线换成 GLSL 1.20 shader（GL 2.1 兼容模式可用，不用改上下文），loader 读全 PBR 贴图。分四步，每步独立验收。

### T8 Shader 核心：PBR-lite 光照 + 色调映射
- 改哪里：`Menu3D.cpp`（InitGL 后编译 shader、绘制时 `glUseProgram`）、`Menu3DModel.cpp`（loader 读贴图、绘制时绑贴图单元与 uniform）。
- 怎么做：
  - 顶点 shader：用内置 attribute（`gl_Vertex` / `gl_Normal` / `gl_MultiTexCoord0`），现有顶点数组不用改；输出世界法线、UV、世界位置。
  - 片元 shader：base color ×（漫反射 Lambert + 镜面 Blinn-Phong，按 roughness 调 shininess、按 metallic 调镜面色）；读 `metallic_roughness_texture`（G 通道 roughness、B 通道 metallic）与 `occlusion_texture`（乘环境光）。
  - 色调映射：片元 shader 末尾做 ACES 近似；输出 sRGB——shader 路径启用时，**停用** `ReadbackToTexture()` 的软件 sRGB 编码（二选一，不要双重编码），并在代码里写明选择。
  - 编译失败回退：shader 编译/链接失败时记日志并回落到固定管线路径，不崩溃；回落逻辑要测（故意写错 shader 验证一次）。
- 验收：与 Blender Eevee 同角度截图并排对比，材质区分明显；编译失败回退验证通过；`gameplay_tests` 通过。

### T9 法线贴图
- 怎么做：loader 读 `normal_texture`；加载时按 UV 算逐顶点切线（简单算法即可，MikkTSpace 风格或按三角形求切线后平均）；顶点 shader 传 tangent，片元 shader 做切线空间法线扰动。
- 验收：砖缝、雕花、布纹等表面细节在近景可见；无切线接缝黑斑。

### T10 方向光阴影
- 怎么做：单张 2048² 方向光阴影贴图，视锥收紧包住场景（只盖菜单相机视野内的范围）；深度贴图 + 片元 shader 采样比对；bias 调到无 acne、无明显 peter-panning 为止。
- 验收：拱门、摊位、廊柱下有真实投影；阴影边缘无明显锯齿与漏光。

### T11 半球环境光（便宜版 IBL）
- 怎么做：片元 shader 里按法线 y 混合天色（上）与地色（下）做半球环境光，取代固定环境光；数值沿用逐场景的 skylight 颜色。
- 验收：背光面不再死黑，仍有明暗层次；不洗掉 T8 的方向光主次关系。

## §6 不可破坏的规则

- 不动游戏本体逻辑（玩法、BOT、教练、经济、回放），只动 `Graphics/Menu3D.*`、`Graphics/Menu3DModel.*`、`Engine.cpp` 的菜单 3D 初始化调用点与相关资源。
- 不改场景美术（模型、布局、材质数量预算不变）；不删除任何东西（no-delete，含旧固定管线路径——P3 完成前保留作回退）；不提交、不 push、不切分支。
- 每阶段独立验证（截图 + validate + 测试）再进下一阶段；一个任务一次做完，中间不等 Sun 确认，但逐阶段校验不能省。
- 不设预算限制（见文首）；`validate_scenes.py` 全程 0 findings；`gameplay_tests` 1750 通过 / 6 失败（基线不变）；`menu_art_review` 通过；性能只记录、不设限。
- 性能回退：不设预算，不降画质；若帧时间明显变差，把实测值写进验收文档报 Sun，由他定夺。
