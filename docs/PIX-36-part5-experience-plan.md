### 0.2 Sun 的决定（2026-11-17 问答，已确认）

1. （1）3 倍适用于**所有**带倍镜的枪（四把狙击 + SG553/AUG）；（2）右键循环保持关 → 1.5 → 3 → 关。

4. （1）按移动距离触发；（2）步幅由 Muse 定；（3）单步音**重新生成**一个；（4）BOT 用同一套；（5）潜行保持静音、开镜步频随减速变慢，保留。
5. （1）对手侧完全隐藏，连“有人在拆包”的提示也不给，只留拆包声；（2）队友侧**只显示剩余秒数**（不显示名字和百分比）；（3）观战的阵亡玩家按自己阵营算。
6. 确认：镜圈里的玩家和 BOT 一样放大显示，镜圈外的玩家仍按原大小留在主场景里。
7. （1）镜头在 1.8 秒内固定在阵亡位置不动、只让世界动；（2）快照机制**整个删掉**；（3）击杀卡和 1.8 秒时长不变。

### 0.3 发行水准要求（Sun 特别强调，本批最高优先级）

**所有的设计都应注重审美体验，必须达到发行水准。** 这不是一句空话，落到每一项的验收里：

- **视觉类（1、3、6、7）**：任何一处改动都必须有进游戏截图/录屏证据，由 Sun 目检通过才算完成。禁止出现：占位感、裁切错误、重影、布局跳变、雾区硬边、HUD 文字溢出或错位、与现有 HUD 视觉语言不一致的新元素。镜内画面、雾遮罩、击杀卡、观战提示的字体、颜色、透明度、圆角、间距，必须与现有界面同一套规范（Palette / GlassPanel / 现有字号层级）。
- **音频类（4）**：新单步音必须由 Sun 耳检通过。脚步节奏必须听起来像“走路”，不是节拍器：步与步之间无可闻的断裂、无双响、无爆音；潜行、开镜、不同移速下的步频变化必须自然。
- **信息类（5）**：信息隔离必须做干净——对手侧不留任何可推断拆包进度的痕迹，包括文字、数字、位置、颜色、布局变化。
- **手感类（2）**：弹速分档以实机手感为准，数值表是起点不是终点；Sun 进游戏实测后有权要求微调档位，不计为返工。
- **回归底线**：`gameplay_tests` 默认模式与 `--experience`（交互会话）必须全过；镜内倍率重测（1.5×/3×，误差 ≤1%）；任何一项的截图证据缺失，都不算完成。

## 1. 开镜倍率调整为 1.5 倍和 3 倍

### 1.1 现状核实

- 档位表 `Presentation::kScopeZoomLevels = { 1.0f, 1.5f, 2.0f }`，`kScopeLevelCount = 3`（`PixelEngine/Core/PresentationContract.hpp:92-93`）；右键循环 `scopeLevel_ = (scopeLevel_ + 1) % kScopeLevelCount`，即关 → 1.5 → 2 → 关（`CS2DGame.cpp:908`）。
- 带镜武器共 6 把（`WeaponDef.scoped == true`）：SSG08、AWP、SCAR-20、G3SG1、SG553、AUG，共用同一套档位；开镜支持由 `IsScopeSupported(cur)` 按武器判定（`CS2DGame.cpp`，`TickScope`）。
- 镜面半径 `kScopeCircleRadiusFrac = 0.42`（屏占比）与换档过渡 `kScopeTransitionSeconds = 0.12f` 与倍率无关，不用动。
- 兼容常量 `kScopeZoomMultiplier = 1.5f`（`PresentationContract.hpp:94`）全仓无调用，是死代码。

### 1.2 修改方案

1. `kScopeZoomLevels` 改为 `{ 1.0f, 1.5f, 3.0f }`；循环逻辑不变（关 → 1.5 → 3 → 关）。
2. 删除未使用的 `kScopeZoomMultiplier` 兼容常量。
3. 更新镜内倍率实测（`tools/buy_scope_test.cpp`，`TestExperienceRendering`）：测量档位改为 1.5× 与 3×，软件渲染 + 真实 D3D11 各测，误差 ≤1%（沿用 15 项计划的测量方法：固定地图特征/标尺量镜内距离）。
4. 核查 3 倍下的镜内内容：镜面以准星世界点为中心，3 倍下镜内世界半径缩小为原来的 2/3，确认镜内不出现空白/内容过少；准星十字、镜面裁剪（128 段三角扇）、镜外暗化均不随倍率改变，无需改动，但截图验收必须覆盖 3 倍。
5. 同步更新 README 玩法清单中“镜内 1.5×/2×”的表述为 1.5×/3×（15 项计划第 14 项改过同一处）。

### 1.3 验收标准

- 右键循环：关 → 1.5 → 3 → 关，6 把带镜枪逐一把验证；非带镜枪右键无反应。
- 镜内实测倍率：1.5× 与 3× 在 D3D11 与软件渲染下误差均 ≤1%；镜心对准准星点；换档 0.12s 平滑过渡无跳变。
- 证据：`build-evidence/experience/` 下 `scope-1.5x.png`、`scope-3x.png`（交互会话重跑产物），Sun 目检通过。

### 1.4 审美要求

- 3 倍镜内画面必须清晰可用（重渲染非拉伸放大，纹理不糊）；镜圈、十字线、镜外暗化在 3 倍下与 1.5 倍视觉一致，无新增瑕疵。

## 2. 每把枪设置各自的子弹速度（游戏性分档）

### 2.1 现状核实

- 子弹速度已是每把枪独立的字段 `WeaponDef.bulletSpeed`（px/s，`WeaponDef.hpp:99`），发射时 `b.vx/vy = cos/sin × def.bulletSpeed`（`CS2DGameCombat.cpp:232-233`）；**问题只在数值**：现值基本按武器类别统一——手枪 1400–1440、冲锋枪 1320–1380、步枪 1240–1280（AK-47 仅 1240，反而比手枪慢）、机枪 1320、霰弹 1200、狙击 2000–2200。狙击只比手枪快约 1.6 倍，880px 宽的地图要飞 0.4 秒，肉眼可见的慢，狙击上手难度高。
- 真实初速参考（2026-11-17 联网核查）：Glock 375、Deagle 470、MP5 约 400、AK-47 约 715、M4 约 880、AWP 约 850 m/s。真实比例下步枪/狙击约为手枪的 2 倍多；本批不做真实单位换算（按真实比例线性映射会使全图接近瞬时命中），而是按真实初速的**相对排序**定游戏性档位。
- 穿透安全已核实：`UpdateBullets` 是扫掠式检测（每帧取 prev→new 线段，`FirstBulletWallFraction` 测墙、沿线段投影采样测命中，`CS2DGameCombat.cpp:285-360`），提速后不存在跨帧穿透（tunneling）风险，无需改命中逻辑。

### 2.2 分档原则与数值表

- 原则：按武器类别分档，档内保留小幅个体差异；排序与真实初速一致（AWP 最快、Deagle 快于 Glock、M4 快于 AK）；狙击在 880px 地图上飞行约 0.16–0.18 秒（约 9–11 帧），接近瞬时但仍可见弹道；手枪仍明显慢于步枪，保留手感差异。
- 仅改 `kWeapons` 表（`WeaponDef.hpp:144` 起）中 `bulletSpeed` 一列；伤害、射程、射速、散布、备弹均不动。

### 2.3 修改方案

1. 按上表逐项改 `kWeapons` 的 `bulletSpeed`（共 34 把枪；霰弹 4 把、手枪 10 把、冲锋枪 6 把、步枪 7 把、机枪 2 把、狙击 4 把，另 Zeus/投掷物/C4/刀不动）。
2. 弹道视觉段核查：`kBulletVisualSeconds = 0.08f` 不变；提速后每帧弹道段变长（AWP 约 93px/帧），属预期效果（看起来更快），只需截图确认曳光观感不怪异；如过长，再调段长上限，不改飞行逻辑。
3. BOT 影响评估（不改 BOT 代码）：子弹变快 → BOT 闪避窗口（`BulletNearRadius` 触发）变短、BOT 狙击更致命。属预期后果；验收时跑现有 BOT 闪避/命中测试，Sun 进游戏实测手感；如 BOT 狙击过强，另立跟进项调 `BulletReactionMul`/瞄准散布，本批不做。
4. 新增高速命中回归测试：AWP（5600 px/s）对最远距离移动 BOT 开火，断言命中登记（无穿透漏检）；各档位 spot-check：每档抽一把枪，断言 `bulletSpeed` 等于表值（防表填错位——`kWeapons` 是位置初始化，错一位即全错）。

### 2.4 验收标准

- 数值表逐项核对无错位；默认回归与 `--experience` 全过；新增高速命中测试通过。
- Sun 进游戏实测：AWP 开镜远距离命中手感明显改善，各档位速度差异可感知；档位数值以 Sun 实测为准，可微调。

### 2.5 审美要求

- 弹道曳光在新速度下观感自然（快而不糊、不拖影）；狙击开火仍有可辨的弹道反馈，不可变成“无弹道瞬移”（完全无弹道会丢打击感）。

## 3. 观战自由视角：队友视野并集 + 修中心视野 bug

### 3.1 现状核实

- **bug 根因已定位**：`DrawWorldPass` 中自由模式的观察者位置正确（`observerX/Y = specFreeX/Y`），但朝向错误——`observerAngle = observer == &player_ ? GetRenderAimAngle() : observerView.aimAngle`（`CS2DGame.cpp:1408`），而 `GetSpectatedPlayer()` 在自由模式下仍返回**进入前跟随的那只 BOT**（`CS2DGame.hpp:924-932`，注释原文“自由视角下保留最后跟随目标”）。于是雾遮罩（`DrawVisionFog(observerX, observerY, observerAngle)`，`CS2DGame.cpp:1510`）与世界可见过滤（`worldVisible`，`CS2DGame.cpp:1410-1414`）都沿用旧 BOT 的朝向，且随其转头而转。
- **并集功能目前不存在**：`SpectatorCanSeeEnemy`（任一队友 BOT 能看到敌人即可见，`CS2DGameSpectate.cpp:100`）全仓无调用，是死代码；实际起作用的只有单视锥过滤。自由模式下只能看到旧 BOT 的 120° 锥内，队友视野不共享。
- **不受影响的部分**：自由镜头位置与移动（WASD，`SpectatorMoveFree`，速度 840）、音频听者（自由模式取 `specFreeX/Y`，`ListenerX/Y`）、跟随模式（单观察者 = 被跟随 BOT，正确）、C4 观战模式（360° 直线视野，正确）。
- 视野参数：半径 `VisionRadius = 200`，锥角 `VisionConeDeg = 120°`（`Tuning.hpp:80,82`）。

### 3.2 Sun 的决定

- 自由视角视野 = 所有队友视锥的并集；跟随模式不动；视野半径与玩家一致（每名队友 200 半径、120° 锥）。

### 3.3 修改方案

1. **视野查询加多观察者接口**：`VisibilityQuery` 增加多观察者重载（如 `ComputeVisibilityUnion(span<const Observer>, x, y)`，`Observer = {x, y, angle}`），返回各观察者 `ComputeVisibility` 的最大值；单观察者行为不变。游戏侧 `visibility_` 与渲染侧 `vis_`（`CS2DRenderer::ComputeVisibility`）共用该接口，避免雾与可见性漂移。
2. **自由模式改用观察者列表**：`DrawWorldPass` 在自由模式下构造观察者列表 = 存活的队友 BOT（`player_.team`，至多 4 只）；`worldVisible` 改为并集判定（任一队友可见即可见，烟雾遮挡仍按各观察者单独判断）；`DrawVisionFog` 接受同一列表，雾像素按并集点亮（任一队友看得到即无雾）。
3. **修朝向 bug**：`GetSpectatedPlayer()` 在自由模式下返回 `nullptr`（改注释与行为）；`SpectatorToggle` 切自由时保留 `specTarget_`（供切回跟随恢复目标），但渲染路径在自由模式下不再使用它。`PrepareCamera` 的自由镜头位置（`specFreeX/Y`）本来就是对的，不动。
4. **观战 HUD 跟随修正**：`Engine.cpp:2526` 的观战状态栏（右下武器栏与左下血量/护甲显示被观战者状态）目前在自由模式下显示旧 BOT 的实时状态；改为自由模式下显示**阵亡玩家本人的最后状态**（冻结态），并在观战提示区增加一行“自由视角 · 队友共享视野”（与现有观战提示同一视觉规范）。
5. **删除死代码**：删除 `SpectatorCanSeeEnemy`（定义 `CS2DGameSpectate.cpp:100` + 声明 `CS2DGame.hpp:1355`）；并集视锥是唯一可见性来源，不留第二套机制。
6. **性能**：雾掩码为低分辨率逐像素循环，观察者至多 4 只，单像素代价 ×4 以内；回归中记录雾耗时（`lastFogMs_`），如显著上升再优化（先并集判定短路：任一观察者可见即停）。

### 3.4 验收标准

- Bug 回归测试：自由模式下，将旧 BOT 的朝向转 180°，断言雾遮罩与可见性不变（与旧 BOT 朝向解耦）。
- 并集测试：两名队友朝向相反，A 能看到的敌人必须在自由视角中绘制且雾区点亮；A、B 都看不到的敌人不绘制；队友本人始终可见（自身即在其视锥原点）。
- 跟随模式与 C4 观战模式行为不变（现有测试覆盖）。
- 证据：自由视角截图（两名队友朝向不同、雾区呈两块亮区），Sun 目检通过。

### 3.5 审美要求

- 并集雾区必须清晰可读：多块亮区之间过渡柔和、与现有雾的软边一致，不出现硬切、锯齿或亮区重叠处的亮度异常；观战提示行与现有 HUD 字体、颜色、位置协调，不挤占其他信息。

## 4. 脚步声按移动距离触发（玩家与 BOT 同一套）

### 4.1 现状核实

- 玩家移速 = 基础 120 px/s × 持械倍率（0.72–1.00）× 开镜 0.6（`Tuning.hpp:26,88`，`CS2DGameCombat.cpp:34-35`）；潜行 50 px/s（`Tuning.hpp:89`）。按持械不同，玩家实际移速约 62–120 px/s。
- 玩家脚步目前是**固定 0.32 秒一步**的循环录音（`sfx_footstep_loop.wav`，1.28 秒 4 步），`PlayFootstepLoop()` 按 `spd > 10.0f` 起停（`CS2DGame.cpp:1202-1203`），与移速无关；听觉事件另用 `footstepTimer_ = 0.32f` 计时（`:1206-1210`）。开镜 AWP（62 px/s）与匕首（120 px/s）用同一个步频，必然不匹配。
- BOT 脚步未改：每只 BOT 固定 `0.34 + (i%5)×0.02` 秒放一次单步音（`CS2DGame.cpp:1101-1109`），同样与移速无关。
- 听觉半径 `FootstepHearRadius = 260`（`Tuning.hpp:169`），记忆 `FootstepMemory = 2.5s`（`:208`），本批不动。
- 技术约束：SDL_mixer 没有循环播放变速接口，固定录音无法跟随移速变步频；精确匹配只能改回按步触发的单步音。

### 4.2 Sun 的决定

- 按移动距离触发；步幅由 Muse 定；单步音重新生成一个；BOT 用同一套；潜行保持静音、开镜步频随减速变慢，保留。

### 4.3 修改方案

1. **步幅定值**：`Tuning::FootstepStride = 28.0f`（= 2 × `PlayerSize` 14.0，即一个身位直径走一步）。对应步频：匕首 120 px/s → 0.23 秒/步；步枪约 96 px/s → 0.29 秒/步；开镜 AWP 约 62 px/s → 0.45 秒/步。数值进 `Tuning.hpp`，可调。
2. **玩家改距离触发**：用实际位移累计（每帧 `|Δpos|`，不是输入速度——卡墙不动时不响）；累计 ≥ 步幅时触发一步，累计减去步幅（保留余数，长期精确）；单帧至多触发 2 步（防卡顿后连响）。触发时：播放单步音（2D）+ `OnFootstepSound` 听觉事件（与音步同频）。删除 `footstepTimer_` 的 0.32 秒计时（听觉事件改随步触发）。
3. **BOT 用同一套**：每只 BOT 各自一个距离累计器（`BotRuntime` 内新增字段）；触发时播放位置化单步音 `PlaySoundAt(FOOTSTEP, …)` + `OnFootstepSound`；删除 `0.34 + (i%5)×0.02` 的固定计时。BOT 移速用其实际位移，天然跟随持械与状态。
4. **单步音重新生成**：Muse 用 ElevenLabs 生成新单步音，替换 `sfx_footstep.mp3` 内容（同路径，BOT 接线不变），-3 dBFS、约 0.10–0.12 秒、单步干净无尾音；Sun 耳检通过为准。
5. **退役循环**：删除 `sfx_footstep_loop.wav`（资产批量新增，本批不再用；本地 `~/workspace/your_files/asset-batch/audio/` 留有副本）与整条循环播放链：`FOOTSTEP_LOOP` 枚举、`CHANNEL_FOOTSTEP_LOOP`、`footstepLoopSound`、`Play/StopFootstepLoop`（`AudioManager.*`）及 `CS2DGame.cpp:1202-1203` 的调用；`Mix_ReserveChannels` 恢复为 12。
6. **边界**：潜行（`stealth`）不累计、不发声；死亡/重生/传送重置累计器；`spd ≤ 10` 视为静止。

### 4.4 验收标准

- 步数测试：玩家以已知速度直线行走已知距离，断言步数 ≈ 距离/28（±1 步）；BOT 同理（抽一只 BOT，步频 ≈ 其移速/28）。
- 卡墙测试：顶墙行走（有输入、无位移）不断言有步声；潜行无声；开镜步频慢于不开镜。
- 听觉事件与步声同频（BOT 听到脚步的时机与声音一致）；现有听觉相关测试全过。
- 新单步音 Sun 耳检通过。

### 4.5 审美要求

- 步声本身必须干净、真实、有质感（新生成音）；节奏听起来像走路而不是节拍器；移速变化时步频过渡平滑，无突兀的快慢跳变；多 BOT 同时走动时位置感清晰、不糊成一片。

## 6. 开镜时玩家在镜内同步放大

### 6.1 现状核实

- **根因已定位**：镜内那一遍世界绘制 `DrawWorldPass(true)` 根本不画玩家——玩家绘制条件是 `if (!lens && !scopedBody && !IsSpectating() && …)`（`CS2DGame.cpp:1442`）；玩家是在镜面合成之后、按主场景比例单独贴上去的（`CS2DGame.cpp:1355-1362`，`SetVisibilityFilter` 仅限直线视野 + 烟雾）。BOT 画在世界绘制循环里（无 `!lens` 限制），所以镜内正常放大。这是 15 项计划第 13 项留下的结构：当时确认的选择是“主场景保留玩家角色”，于是玩家画在镜面之上、主场景比例——现在 Sun 要求镜内同步放大。
- 镜面合成：`BeginScopeScene(aimX, aimY, centerX, centerY, scope.zoomMultiplier)` → `DrawWorldPass(true)` → `EndScopeScene()` → `DrawScopeScene(...)` → `DrawScopeOverlay(op)` → 玩家贴图（`CS2DGame.cpp:1349-1362`）。
- 镜圈世界半径 = `scopeRadiusPx / (主场景 zoom × scope.zoomMultiplier)`，其中 `scopeRadiusPx = 0.42 × min(viewW, viewH)`。

### 6.2 修改方案

1. **镜内画玩家**：`DrawWorldPass(true)` 中也绘制玩家（与 BOT 同一套 `MakeActorDrawParams` + `ownBodyVisible` 过滤），即去掉玩家绘制的 `!lens` 限制（保留存活等其他条件）；镜内玩家随世界一起放大。
2. **镜外保留原大小**：`Render()` 中镜面合成后的玩家贴图改为**仅当玩家在镜圈外时**绘制：判定条件为玩家到准星世界点的距离 > 镜圈世界半径 + 玩家半径（`player_.size`，留边距防边界闪烁）；在镜圈内时不画（镜内放大版已覆盖），避免同一玩家一大一小重影。
3. **边界说明**：玩家横跨镜圈边缘时按中心点二选一，允许 1–2 帧的边界切换观感，不做逐像素裁剪（SDL2 无圆形裁剪，逐像素方案成本过高）。
4. 玩家武器随角色同一绘制调用，镜内自动同步放大，无需另处理；准星十字与镜面覆盖层不受影响。

### 6.3 验收标准

- 镜内玩家尺寸比：玩家在镜圈内时，镜内角色高度 / 主场景角色高度 ≈ 当前镜内倍率（1.5×/3×，误差 ≤10%）；镜圈外玩家保持原大小。
- 无重影：玩家跨越镜圈边缘时无一大一小双重影像；截图逐帧检查。
- 扩展倍率实测：`TestExperienceRendering` 增加“镜内玩家”断言；证据 `scope-1.5x.png` / `scope-3x.png` 中玩家位于镜圈内，Sun 目检通过。

### 6.4 审美要求

- 镜内玩家与 BOT 的放大观感一致（同一套绘制路径）；镜圈边缘处玩家进出过渡自然，无闪烁、无残影。

## 7. 阵亡后 1.8 秒内画面继续直播（删除定格快照）

### 7.1 现状核实

- **现状是 15 项计划第 5 项特意做的设计**：死亡瞬间画面渲染一次存成快照纹理 `deathWorldTex_`，1.8 秒内反复贴同一张图（`Engine::DrawGameplayWorld`，`Engine.cpp:1990-2016`）；后台对局继续跑（BOT、炸弹、回合推进不停），但画面不动。Sun 现在要求改成直播，即推翻该设计。

- 快照机制的全部位置：`deathWorldTex_` / `deathWorldEvent_` 成员、`ClearDeathSnapshot()`（定义 `Engine.cpp:1984-1987`，调用点 `:107, :234, :847, :1992`）、`DrawGameplayWorld` 的快照分支（`:1997-2015`）。

### 7.2 修改方案

2. **镜头保持固定**：`PrepareCamera` 的定格期提前返回不动——1.8 秒内镜头固定在阵亡位置，只让世界动（BOT 走位、炸弹计时、伤害数字、击杀播报均实时推进）。

### 7.3 验收标准
