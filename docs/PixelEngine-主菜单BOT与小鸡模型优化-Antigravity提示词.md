# 主菜单 BOT 与小鸡模型优化：倒角 + 圆滑 + 细分（Antigravity 提示词）

> 用法：全文直接粘贴给 Antigravity 的 agent。MCP 已配好 + blender-skills 综合使用。
> 关键：5 个模型（2 个 BOT 文件 + 1 个小鸡文件）一个任务同时做，每个模型独立验收，中间不等 Sun 确认，但每个做完都要截图 + 校验通过才算完。
> 现状依据：Menu3D.cpp（2026-11-24 读过的版本）里的加载逻辑——文件路径、动画名、高度常量都是从代码里核实的，不是猜的。

## 任务一句话
给主菜单的两个 BOT（T、CT）和三只小鸡做一轮模型优化：所有硬边加倒角、所有曲面变圆滑、棱面加段数。不动位置、原点、整体高度、动画和玩法。

## 目标模型（从代码核实）
- BOT（两只，左右两侧角色）：`assets/models/menu/t.glb`（T，x=-3.6）和 `assets/models/menu/ct.glb`（CT，x=+3.6），动画剪辑 `Menu_Idle_AK`（持 AK 待机）。两个文件分别优化，标准一致。
- 小鸡（三只，同一文件的三个实例）：`assets/models/menu/chicken.glb`，位置由代码定（x -2.35/0.0/2.25，z 3.2/5.4/3.0），4 个动画剪辑必须全部保留在导出文件里：`Menu_Walk`、`Menu_Idle`、`Menu_Look`、`Menu_Rest`（游戏启动会逐个检查，缺一个就报“小鸡动画缺失”）。
- 小鸡模型本身没有材质：羽色是游戏代码整体覆盖的（7 种颜色），不要给小鸡加贴图或新材质，保持无贴图/单一材质，否则配色覆盖会出问题。
- 小鸡模型高 `kChickenModelHeight = 1.843` 单位：游戏用这个常量算步幅和世界缩放，高度、原点（脚底中心）、整体缩放一律不许动；BOT 也一样，原点和整体高度不许动，否则站位和取景全歪。
- 程序画的备用小鸡（Menu3D.cpp 里的 DrawChicken，球+方块拼的）只是后备/预览用的，不要碰代码，只改 GLB。

- 源文件定位（第一步先做）：t/ct/chicken 三个模型的 .blend 源可能在 `assets/models/menu/` 或 `tools/menu-scenes/` 下，也可能只有 GLB 没有 .blend——先全盘找，找到哪个用哪个；只有 GLB 时就导入 GLB 改，改完这个 .blend 就是新的源文件，记下来。

## 用哪个 skill（按步骤）
- BOT（装甲人形，头盔/护甲/手里的 AK 都是硬表面）：**blender-hardsurface-modeling**，走 Mid-poly 工作流（倒角 + Weighted Normal，不烘焙，直接出游戏网格）。不要走 Subdivision 工作流，也不要走 High → low 烘焙（除非某件东西细部实在要用法线贴图）。
- 小鸡（有机体）：没有专用的有机建模 skill，就用同一套数字 + 一级 Subdivision（只对真正弯曲、加段数也救不了的部位：身体、头部），加支撑环/折痕定住边；喙、鸡冠、肉垂、尾巴、腿脚按小件硬表面处理（倒角 + 光滑着色）。
- 拓扑太乱的地方：blender-retopology-uv（四边面为主，倒角/细分不夹角）。
- 材质：blender-pbr-materials（只给 BOT 用；小鸡不加材质，见上）。
- 导出：blender-export-pipelines（glTF 导出必须带齐动画剪辑）。
- 检查：blender-asset-qa，每个模型做完跑一遍，不过不算完。

## 怎么做：5 个模型一个任务同时做
- 一个任务覆盖 t.glb、ct.glb、chicken.glb 三个文件，中间不等 Sun 确认，直接往下做。
- 每个模型是独立单元：先列清单 → 动手 → 多角度截图 + 特写截图 → 跑校验，通过才算这个做完，再做下一个。不要全做完才第一次检查。
- 不要开多个会话同时改同一个仓库：三个 GLB 和共用的脚本/校验文件是共用的，并行写会互相覆盖。
- 顺序：先做两只 BOT（t 再 ct，或 ct 再 t），再做小鸡（一个文件，三只实例一次受益）。

## 优化标准（数字，不是形容词）
BOT（两只，标准一致）：
1. 倒角：所有硬边（头盔沿、护甲板边、护膝/护肘边、AK 的机匣/弹匣/护木边）加倒角，宽度按部件尺寸的 0.5–2%（大件护甲板 2–4cm，小件配件 0.5–1cm），2–3 段，limit_method="ANGLE"（30°），harden_normals 开，miter_outer="MITER_ARC"，use_clamp_overlap 开。
2. 段数：枪管/枪口/关节圆柱 ≥24 段；头盔穹顶 ≥32 段；圆环/瞄具 ≥24 段。不要用默认 12 段、16 段的圆柱。
3. 着色：所有曲面光滑着色（Shade Smooth by Angle）+ Weighted Normal（mode="FACE_AREA"，keep_sharp，weight 50）；平面保持平直，平面上不许出现渐变 shading。
4. 细分：只对真正弯曲、加段数也救不了的形体用一级 Subdivision（头盔、肩甲弧面），加支撑环/折痕定住边；不要全场细分。
5. 拓扑：倒角和细分的面以四边面为主，不许出现大面积三角面和 N-gon；先 Apply Scale 再加倒角/布尔，不然倒角宽度会歪。
6. 顺序：先修看得见的地方（主相机、聚焦相机能看到的面：正面、头盔、胸甲、手里的 AK），再修背面和犄角旮旯。
小鸡（一个文件）：
1. 身体/头部：球体分段不够就加段数，光滑着色 + Weighted Normal；还显棱就一级 Subdivision 加支撑环。身体和头部不许出现肉眼可见的棱面。
2. 喙、鸡冠、肉垂、尾巴、腿脚：小件，各自加倒角（0.5–1cm 量级，按部件尺寸的 0.5–2%），光滑着色；腿（细圆柱）≥16 段；眼睛保持独立球体，光滑着色。
3. 羽毛：如果羽毛是独立几何体，保持独立部件，不要并进身体；如果羽毛只是贴图/材质效果，不要动材质（小鸡不加材质，见上）。
4. 骨架/动画：不动骨架、不动 4 个剪辑的名字和长度；改完导出后逐个验证剪辑都在（Menu_Walk、Menu_Idle、Menu_Look、Menu_Rest）。
5. 高度/原点/缩放：不许动（kChickenModelHeight = 1.843，游戏靠它算步幅）。

## 预算（不设上限，只记录实测值）
- Sun 2026-11-24 已定：主菜单美术不设预算限制。顶点数、GLB 体积、材质数、贴图尺寸、初始化耗时一律不设上限，只记录实测值写进验收；帧时间变差也不降画质，只把数字报给 Sun 定夺。

## 操作流程（MCP）
1. 先验证 MCP 连通（新建一个立方体并改名），通了再开始；Blender 里先 get_scene_info + 截图看现状再动手。
2. 先定位源文件（见“前提”）：列出 t/ct/chicken 各自的源文件路径（.blend 或 GLB 导入）、当前顶点数、材质数、动画剪辑清单，再动手。
3. 每个模型：先列一张“要修的清单”（哪些部件、哪种修法、预计加多少顶点），再动手；做完用主相机、聚焦相机两个机位截图 + 特写截图（之前棱面最明显的 2–3 处）检查。
4. 导出 GLB（t.glb、ct.glb、chicken.glb，覆盖原文件前先备份原 GLB 到 build-evidence/menu-characters/ 下）；导出后验证：BOT 的 Menu_Idle_AK 在、鸡的 4 个剪辑全在；进游戏看主菜单，控制台应出现 “[Menu3D] glTF 角色已加载: T=Menu_Idle_AK CT=Menu_Idle_AK 小鸡=3” 且没有任何“动画缺失”报错；再跑 blender-asset-qa。
5. 如果模型是脚本生成的（tools/menu-scenes/ 下有对应脚本），把建造逻辑写进脚本（保证可重复生成，不要只改 .blend 不改脚本）；如果只有 .blend/GLB，把 .blend 存为新的源文件并记下路径。
6. 改动留工作区，不提交、不 push，等 Sun 过目。

## 保护区（底线）
- 不动模型位置、原点、整体高度、整体缩放（位置是代码定的，见“目标模型”）。
- 不动相机参数（主相机 eye (0, 1.05, 8.0)、look (0, 0.95, 0)）、加载逻辑、0.5 秒切换、预览抓拍。
- 不动三张场景 GLB、不动武器模型（focusWeapons 的 AK/手枪/刀）、不动程序画的备用小鸡和灰尘代码。
- 每层做完用主相机、聚焦相机两个机位截图检查：BOT 不能挡住主菜单按钮，小鸡不能飘出地面或挡住按钮。

2. 不删除任何现有模型、材质、动画、决策或数据。
3. 不用 Valve 原版资产；新用到的第三方素材只用 CC0 / CC-BY，来源与授权写进 assets/models/CREDITS.md。
4. 不涉及随机数；如需随机性，走独立的 rng_humanizer_，绝不碰全局 rng_。
