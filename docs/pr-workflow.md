# 分支与 PR 流程

所有改动走「分支 → PR → 合并」，不直接推 `main`。

## 分支命名

| 前缀 | 用途 |
| --- | --- |
| `feat/` | 新功能 |
| `fix/` | 修 bug |
| `docs/` | 文档 |
| `refactor/` | 重构（行为不变） |
| `chore/` | 配置、依赖、脚本等杂项 |

## 步骤

1. 更新 `main`：`git switch main` 后 `git pull`
2. 开分支：`git switch -c feat/xxx`
3. 提交：一次提交只做一件事，信息写清做了什么
4. 推送：`git push -u origin feat/xxx`
5. 开 PR 到 `main`，描述写三件事：改了什么、为什么改、怎么验证
6. 评审通过后合并，删除远程分支

## 约定

- 一个 PR 只解决一个问题，改动尽量小，便于阅读和回滚
- 不把「全仓库格式化」「批量重命名」和功能改动混在同一个 PR
- 合并前确认能编译通过
